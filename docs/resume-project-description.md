# PaperMind 简历项目描述

本文档用于整理 PaperMind 的简历写法、面试讲法和项目亮点。

## 一句话介绍

PaperMind 是一个面向论文和长文档阅读的 AI 文档助手，支持 PDF/Markdown/TXT 上传、文本解析、RAG 问答、引用溯源、文档洞察、流式回答和 Agent 工具生成学习材料。

## 简历版描述

```text
独立开发 PaperMind AI 文档阅读平台，基于 Next.js、TypeScript、FastAPI 和 Python 实现文档上传、文本解析、本地向量索引、混合检索、基于引用的多轮问答、文档洞察、流式回答、Markdown 笔记导出和 Agent 工具调用。封装 SiliconFlow DeepSeek 模型调用层，并在模型不可用时提供本地抽取式兜底回答；后端实现工具注册表、统一错误返回、请求日志、限流、任务重试、问答缓存、Token 和费用记录，并通过 pytest 与 Playwright 覆盖核心链路和边界场景。
```

## 简历要点版

- 基于 Next.js + TypeScript + FastAPI 构建 AI 文档阅读平台，完成文档上传、解析、切分、检索、问答、洞察和 Agent 工具生成闭环。
- 实现本地哈希向量索引与关键词混合检索，回答时返回引用片段，Prompt 限制模型只能基于检索内容回答，降低幻觉风险。
- 封装 SiliconFlow DeepSeek Chat Completions 调用层，支持流式输出、超时重试、Token 统计、费用估算和模型不可用时的本地兜底。
- 设计多轮会话历史管理，支持历史上下文传入、长上下文压缩和独立问题缓存，避免缓存污染多轮对话。
- 建立 Agent 工具注册表，提供摘要、关键词、复习题、Markdown 笔记和汇报大纲生成，工具结果同时返回 Markdown 和结构化 JSON。
- 补齐工程化能力：统一错误返回、请求 ID、基础限流、文档处理重试、幂等上传、Redis 异步队列、日志页和 Playwright E2E 测试。

## 面试讲解结构

### 1. 项目背景

我想做的不是一个简单聊天框，而是一个完整的 AI 应用落地链路：用户上传文档后，系统能解析、切分、检索、问答、引用溯源，并进一步生成摘要、提纲、复习题和笔记。

### 2. 核心链路

1. 文档上传：校验类型和大小，计算 SHA-256 做幂等。
2. 文档解析：PDF 使用 pypdf，Markdown/TXT 走文本解析。
3. 文档切分：按页码、段落和长度切成 chunks。
4. 检索：结合关键词和本地向量相似度召回片段。
5. 问答：把引用片段、问题和会话历史拼成 Prompt 调用模型。
6. 引用：回答返回引用片段，前端展示原文来源。
7. 兜底：模型不可用时用本地抽取式回答，保证演示稳定。
8. Agent 工具：将摘要、关键词、复习题、笔记和汇报大纲封装为工具。

### 3. 技术亮点

- RAG 闭环完整：解析、切分、向量化、检索、Prompt、引用展示都已落地。
- 输出可控：问答要求固定结构，文档洞察使用 JSON Schema 校验。
- 稳定性处理：模型超时、解析失败、文件过大、格式错误、重复上传都有边界处理。
- 可观测性：记录请求 ID、模型日志、Token、费用、缓存命中和失败原因。
- 工具调用能力：后端有显式工具注册表，不只是页面按钮，便于后续接入模型计划器。
- 测试覆盖：后端 43 个 pytest，前端 E2E 覆盖上传、Agent 工具和问答主流程。

## 可量化表述

- 支持 3 类文件格式：PDF、Markdown、TXT。
- 支持 5 个 Agent 工具：摘要、关键词、复习题、Markdown 笔记、汇报大纲。
- 后端测试 43 个用例，覆盖上传、解析、检索、问答、模型异常、缓存和 Agent 工具。
- E2E 覆盖真实浏览器中的上传、阅读、工具调用、问答和错误提示。

## 面试问答准备

### 为什么要做引用溯源？

普通聊天式回答很难判断依据来自哪里。PaperMind 在回答时返回 citation，前端展示原文片段，让用户能核对模型回答是否有文档依据，也方便在 Prompt 中限制模型不要伪造页码或引用。

### 模型不可用怎么办？

我做了两层兜底：问答接口在没有 Key、没有引用或模型超时时，会使用本地抽取式回答；文档洞察在模型输出异常或 JSON 校验失败时，会回退到本地启发式摘要和关键词提取。

### 怎么处理长对话？

会话历史会传入模型，但不会无限增长。系统会保留最近消息，并把较早历史压缩成系统摘要，避免上下文过长影响请求稳定性。

### 为什么当前用本地 JSON？

这是作品集 MVP 的取舍。本地 JSON 更容易演示和部署，数据结构按照逻辑表设计，后续可以迁移到 PostgreSQL；向量部分也可以迁移到 pgvector 或专用向量数据库。

### Agent 工具和普通按钮有什么区别？

后端把能力封装在工具注册表里，每个工具有统一名称、描述、执行入口和结构化返回。前端只是调用工具接口。后续可以加模型计划器，让模型根据用户意图选择工具或组合工具，扩展成更完整的 Agent 工作流。
