# RAG 文档问答系统设计笔记

RAG 的核心目标是让大模型回答时依赖外部知识库，而不是完全依赖模型参数中的记忆。一个典型流程包含文档解析、文本切分、向量化、检索、上下文拼接和答案生成。

在 PaperMind 中，文档会先被解析成多个片段。每个片段保留页码、顺序和原文内容。用户提问时，系统先检索与问题最相关的片段，再把这些片段作为上下文交给模型。

引用溯源是降低幻觉的重要策略。回答中需要展示引用片段，让用户判断答案是否真的来自文档。当检索片段不足以回答问题时，系统应该明确说明依据不足，而不是生成看似合理但无法验证的内容。

长文档处理需要关注性能和成本。解析任务适合放到异步队列中执行，模型调用需要设置超时、重试和日志记录。对于高频问题，可以使用缓存减少重复调用。

第一版产品应优先保证上传、解析、检索、问答和引用展示这条核心链路稳定，再逐步扩展摘要、提纲、笔记导出和 Agent 工作流。
